# Phase 2 — Tool-schema compression (Tscg)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** Losslessly compress the JSON tool schemas embedded in the prompt so the
static agentic prefix (Claude Code: ~27 tools) shrinks ~40–50%, making even the
COLD first turn faster and using less KV-cache RAM. Based on Tscg (arXiv 2605.26165).

**Architecture:** A pure `tscg` module turns each `ToolSpec` into a compact textual
form. `engine_llama::build_prompt` uses it for the `<tools>` block instead of
verbose pretty JSON. Tool-calling output parsing is unchanged (the model still
emits `<tool_call>{json}</tool_call>`).

**Tech Stack:** Rust, serde_json.

## Global Constraints

- **Lossless in practice:** all semantic content (tool name, every parameter, its
  type, enum values, required-ness, and a usable description) must survive. The
  tool-calling acceptance scripts MUST still pass after compression.
- Compression is deterministic and rule-based (no LLM). No new heavy deps.
- Only `engine_llama`'s tool serialization changes; the `<tool_call>` OUTPUT
  parsing and the api/* layers stay as they are.
- Measure and report the real token reduction on a representative tool set.

### Task 1: `tscg` module — compact tool serialization

**Files:**
- Create: `src/tscg.rs`
- Modify: `src/lib.rs` (`pub mod tscg;`)
- Test: inline unit tests

**Interfaces:**
- Produces: `pub fn compact_tool(tool: &ToolSpec) -> String` and
  `pub fn compact_tools_block(tools: &[ToolSpec]) -> String` returning the full
  `<tools>…</tools>` inner text in compact form.

Compression rules (conservative, lossless):
- Minify JSON (no insignificant whitespace).
- Drop schema boilerplate that carries no selection signal: top-level
  `"type":"object"`, `"additionalProperties"`, `"$schema"`, empty `"description"`,
  `"title"`. Keep parameter names, `type`, `enum`, `required`, and non-empty
  descriptions.
- Represent each tool as one compact line, e.g.:
  `name(p1:type!, p2:type=enum[a,b], p3:type) — description`
  where `!` marks required and `=enum[...]` lists allowed values. Parameters with
  descriptions append them compactly. (Pick a single consistent grammar and
  document it; the model only needs a clear, unambiguous listing.)

- [ ] **Step 1: Failing tests**
  - A tool with one required string param + one enum param compacts to a string
    that CONTAINS the tool name, both param names, the enum values, and the
    required marker, and is SHORTER than `serde_json::to_string_pretty` of the
    same schema. Assert `compact.len() < pretty.len()` and key substrings present.
  - `compact_tools_block` wraps each tool on its own line.
- [ ] **Step 2: Run → fail** (`cargo test --lib tscg`).
- [ ] **Step 3: Implement** the rules above. Walk the `parameters` JSON Value
  (object with `properties` + `required`), emit the compact grammar. Be robust to
  missing fields.
- [ ] **Step 4: Run → pass.**
- [ ] **Step 5: Token-reduction check** — add a test (or a `#[test]` printing
  via `--nocapture`) over a realistic 5-tool set asserting the compact block is
  ≤ 60% the size of the pretty-JSON block (chars as a token proxy).
- [ ] **Step 6: Commit** `feat(phase2): tscg compact tool serialization`.
