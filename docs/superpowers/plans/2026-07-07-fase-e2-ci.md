# Fase E2 — CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a GitHub Actions workflow that builds and tests `localllm` across the five E1 backend×OS configs on every push and PR, with a blocking `fmt` gate and an informational `clippy` step — preceded by a one-time rustfmt baseline so the fmt gate is green from the first push.

**Architecture:** Two deliverables. (1) A one-time `cargo fmt --all` reformat of the whole tree (a `style:` commit) — the codebase has never been rustfmt-formatted. (2) `.github/workflows/ci.yml` with a `lint` job (fmt blocking + clippy informational) and a `build-test` matrix (macOS/metal + Linux/Windows cpu = build+test; Linux/Windows cuda = build-only).

**Tech Stack:** GitHub Actions, `dtolnay/rust-toolchain`, `Swatinem/rust-cache`, `Jimver/cuda-toolkit`, rustfmt, clippy.

## Global Constraints

- **fmt gate is blocking; clippy is NOT** — the clippy step runs WITHOUT `-D warnings` (informational). Do not add `-D warnings`. Do not fix clippy warnings, touch `server.rs` lock scopes, or refactor `too_many_arguments` in E2.
- **The fmt baseline is mechanical, zero behavior change** — applied via `cargo fmt --all` only; no hand edits. The test suite must stay green after it.
- **Triggers:** `push` (any branch) + `pull_request` targeting `main`.
- **Matrix (5 cells, `fail-fast: false`):** macos-14/metal (build+test), ubuntu-latest/cpu (build+test), windows-latest/cpu (build+test), ubuntu-latest/cuda (build-only), windows-latest/cuda (build-only). Encoded via `matrix.include`.
- **cuda cells are build-only** (no GPU on hosted runners).
- **Scope fence:** no release/artifacts/versioning (E3), no GPU runtime, no Vulkan/ROCm cells.
- **The workflow YAML cannot be run locally** — its runtime correctness is validated by the user's first push. Local verification is limited to YAML well-formedness and structural correctness against this plan.

  `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>` and

### Task 2: CI workflow (`.github/workflows/ci.yml`)

**Files:**
- Create: `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: the rustfmt-clean tree from Task 1 (so the `cargo fmt --all --check` step passes); the E1 cargo features `metal`/`cuda`/`cpu`.
- Produces: nothing consumed by later E2 tasks (terminal task). E3 will later add a separate `release.yml`.

- [ ] **Step 1: Create the workflow file**

Create `.github/workflows/ci.yml` with EXACTLY this content:
```yaml
name: CI

on:
  push:
  pull_request:
    branches: [main]

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  lint:
    name: fmt + clippy
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Install system deps
        run: |
          sudo apt-get update
          sudo apt-get install -y \
            libwebkit2gtk-4.1-dev libgtk-3-dev \
            libayatana-appindicator3-dev libxdo-dev cmake libclang-dev
      - uses: dtolnay/rust-toolchain@stable
        with:
          components: rustfmt, clippy
      - uses: Swatinem/rust-cache@v2
        with:
          key: lint
      # Blocking: the tree is kept at a rustfmt baseline (Fase E2 Task 1).
      - name: Format check
        run: cargo fmt --all --check
      # Informational only — NO `-D warnings`. Surfaces clippy findings in the
      # log without failing CI (user decision, Fase E2 spec).
      - name: Clippy (informational)
        run: cargo clippy --workspace --all-targets --features cpu

  build-test:
    name: ${{ matrix.os }} / ${{ matrix.backend }}
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        include:
          - os: macos-14
            backend: metal
            run_tests: true
          - os: ubuntu-latest
            backend: cpu
            run_tests: true
          - os: windows-latest
            backend: cpu
            run_tests: true
          - os: ubuntu-latest
            backend: cuda
            run_tests: false
          - os: windows-latest
            backend: cuda
            run_tests: false
    steps:
      - uses: actions/checkout@v4
      - name: Install Linux system deps
        if: runner.os == 'Linux'
        run: |
          sudo apt-get update
          sudo apt-get install -y \
            libwebkit2gtk-4.1-dev libgtk-3-dev \
            libayatana-appindicator3-dev libxdo-dev cmake libclang-dev
      - name: Install CUDA toolkit
        if: matrix.backend == 'cuda'
        uses: Jimver/cuda-toolkit@v0.2.19
        with:
          cuda: '12.5.0'
          method: network
      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2
        with:
          key: ${{ matrix.os }}-${{ matrix.backend }}
      - name: Build
        run: cargo build --features ${{ matrix.backend }}
      # cpu/metal cells run the (pure, model-free) suite; cuda cells are
      # build-only — hosted runners have no NVIDIA driver.
      - name: Test
        if: matrix.run_tests
        run: cargo test --features ${{ matrix.backend }}
```

- [ ] **Step 2: Validate YAML well-formedness**

The workflow cannot be executed locally, but its YAML must parse and the job
structure must be intact. Run:
```bash
python3 -c "import yaml,sys; d=yaml.safe_load(open('.github/workflows/ci.yml')); assert set(d['jobs'])=={'lint','build-test'}, d['jobs'].keys(); m=d['jobs']['build-test']['strategy']['matrix']['include']; assert len(m)==5, len(m); assert sum(1 for c in m if c['run_tests'])==3; assert sum(1 for c in m if not c['run_tests'])==2; print('ci.yml OK: 2 jobs, 5 matrix cells, 3 test + 2 build-only')"
```
Expected: `ci.yml OK: 2 jobs, 5 matrix cells, 3 test + 2 build-only`.
(Note: PyYAML parses the `on:` key as the boolean `True` — that is a known
PyYAML quirk and does not affect GitHub's parsing; the assertions above avoid
relying on the `on` key.)
