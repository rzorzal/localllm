# Quant tier (sub-project 2)

**Date:** 2026-07-01
**Status:** Approved design, ready for planning
**Scope:** Sub-project 2 of 3. Per-model GGUF quantization-variant selection.
**Depends on:** Sub-project 1 (per-model execution profile) — branch from
`feat/per-model-exec-profile`, not `main`.

## Context

Sub-1 gave each model a saved execution profile (ctx, kv_type, gpu_layers,
history_turns) with a per-model recommended default. It deliberately left one
knob out: **which GGUF quantization variant** to run. Today every catalog model
is pinned to a single `Q4_K_M` file. This sub-project lets the user pick a
quant variant per model — a smaller quant (Q3_K_M, Q2_K) to fit a larger model
in less RAM (the AirLLM-adjacent goal), or a larger quant (Q5_K_M, Q6_K, Q8_0)
for higher quality when RAM allows.

The AirLLM motivation and platform caveats are recorded in the sub-1 spec
(`2026-07-01-per-model-exec-profile-design.md`). On Apple unified memory, lower
quant is one of the few genuinely effective levers for fitting a bigger model,
so this knob carries real weight.

## Goals

- A curated set of quant variants per model, with accurate file lists and sizes.
- Per-model persisted selection, defaulting to the current `Q4_K_M`.
- Fit estimate + status (downloaded / needs-download) computed **per variant**.
- Download + load the selected variant (including multi-file split quants).
- A quant selector in the model-picker drilldown.
- Runtime stays fully offline: variant data is baked into the binary.

## Non-goals

- IQ-family quants (IQ4_XS, etc.) — availability across repos is irregular;
  deferred. Target set is the K-quants only (below).
- Tool filtering (sub-3).
- Runtime HuggingFace queries on the serving path. The only network access is a
  dev-time harvest script (below).

## Target quant set

`Q2_K`, `Q3_K_M`, **`Q4_K_M` (default)**, `Q5_K_M`, `Q6_K`, `Q8_0`. A quant that
does not exist in a given repo is simply omitted from that model's variant list.
Every model retains its existing `Q4_K_M` entry as the default variant, so a
model with no other harvested quants still works exactly as today.

## Architecture

### 1. Data acquisition — harvest script

A committed dev-time binary `src/bin/harvest_quants.rs` (`cargo run --bin
harvest_quants`):

- For each unique `repo` in `CATALOG`, calls the HuggingFace tree API
  (`https://huggingface.co/api/models/{repo}/tree/main`, JSON: `[{path, size},
  …]`).
- Filters `.gguf` files whose name contains one of the target quant tags
  (case-insensitive match on the tag, e.g. `q4_k_m`).
- Groups split files: a name matching `-\d{5}-of-\d{5}\.gguf` belongs to a
  multi-file variant; files sharing the same prefix + quant tag are one variant,
  sorted by shard index. Sums their `size` bytes → `size_mb` (rounded).
- Emits a generated, committed Rust source file `src/catalog_variants.rs`:

```rust
// @generated by `cargo run --bin harvest_quants` — do not edit by hand.
use crate::catalog::QuantVariant;

pub static QUANT_VARIANTS: &[(&str, &[QuantVariant])] = &[
    ("Qwen/Qwen2.5-3B-Instruct-GGUF", &[
        QuantVariant { quant: "Q2_K",   files: &["qwen2.5-3b-instruct-q2_k.gguf"],   size_mb: 1274 },
        QuantVariant { quant: "Q4_K_M", files: &["qwen2.5-3b-instruct-q4_k_m.gguf"], size_mb: 2000 },
        // …
    ]),
    // …
];
```

- The script is idempotent and re-runnable to refresh the table. It **merges**:
  it starts from the current `QUANT_VARIANTS` (parsed or, simpler, re-declared by
  re-reading it as a linked module), updates only the repos it successfully
  fetched this run, and leaves a failed repo's prior data intact — so a transient
  network failure never drops good data. It prints a summary (repos processed,
  variants found, repos skipped due to fetch failure, and repos where the default
  `Q4_K_M` file was NOT found — a data-integrity warning). The generated file is
  written once, at the end, from the merged result.

The script depends on `reqwest` (already a dependency) + `serde_json`. It is not
compiled into the server binary's normal path (separate `[[bin]]`).

### 2. Catalog model

In `src/catalog.rs`:

```rust
#[derive(Debug, Clone, Copy, serde::Serialize)]
pub struct QuantVariant {
    pub quant: &'static str,
    pub files: &'static [&'static str], // >1 = split model
    pub size_mb: u32,
}

/// Variants for a repo: the generated table, or a single-element fallback
/// synthesized from the CatalogEntry's default file when the repo is absent.
pub fn variants_for(entry: &CatalogEntry) -> Vec<QuantVariant>;
```

`variants_for` looks the repo up in `crate::catalog_variants::QUANT_VARIANTS`.
If found, returns that slice (as a Vec for a uniform return type); otherwise
returns a one-element Vec built from `entry.quant`/`entry.file`/`entry.size_mb`
so behavior is unchanged for un-harvested repos. `CatalogEntry` is unchanged.

`ModelView` gains:

```rust
pub variants: Vec<VariantView>,
pub quant_selected: String, // the resolved active quant tag for this model
```

with

```rust
#[derive(Debug, Clone, serde::Serialize)]
pub struct VariantView {
    pub quant: String,
    pub size_mb: u32,
    pub est_ram_mb: u32,
    pub fit: FitVerdict,
    pub status: ModelStatus, // downloaded / needs_download (per this variant's files)
    pub selected: bool,
}
```

`catalog_view` computes each `VariantView`'s fit/est_ram using that variant's
`size_mb` (same KV-aware math as today, swapping `size_mb`), and its status via
the injected `is_downloaded` probe applied to the variant's files. The model row's
top-level `size_mb`/`est_ram_mb`/`fit` reflect the **selected** variant.

### 3. Selection persistence (extends sub-1)

`ExecProfile` (from sub-1) gains:

```rust
#[serde(default, skip_serializing_if = "Option::is_none")]
pub quant: Option<String>, // chosen quant tag, e.g. "Q5_K_M"
```

Resolution: `saved.quant → entry default (`Q4_K_M`, i.e. the `CatalogEntry.quant`)`.
There is no catalog "recommended quant" tier in this sub-project (the default
variant is the recommendation). The settings key stays `"{repo}/{file}"` (the
model's default file) via the existing `model_ctx_key` — quant is a field under
that one model key, alongside ctx/kv/gpu/history.

`profile::Resolved` (sub-1) gains `quant: String` (the resolved tag). A helper
resolves the selected variant's file list:

```rust
// in catalog.rs
pub fn files_for_quant<'a>(entry: &CatalogEntry, quant: &str) -> Option<&'static [&'static str]>;
```

returning the matching variant's `files`, or `None` if that quant is not
available for the model (caller falls back to the default file).

### 4. Load / switch / download

`ModelSpec` gains `quant: Option<String>` (`#[serde(default)]` for back-compat;
`None` = the default `Q4_K_M`). Equality now includes `quant`, so switching quant
on the same model is a real switch.

- The `EngineBuilder` closure (sub-1, `lib.rs`) resolves the profile as today,
  then resolves the variant's files via `files_for_quant(entry, &resolved.quant)`
  (falling back to `[spec.file]` when absent) and passes that file list to
  `LlamaEngine::load` (which already takes `gguf_files: &[String]`).
- The switch endpoint (`/admin/model`) accepts an optional `quant` in its body;
  it builds a `ModelSpec { repo, file, quant }` and switches. Selecting a
  different quant for the active model routes through the normal switch/drain/
  reload path.
- Download: `ensure_model(repo, &variant.files)` — already multi-file capable.
- Status probe: a variant is `Downloaded` only when ALL its files are present.
- Delete (`/admin/models` DELETE): deletes a specific variant's files (body gains
  optional `quant`; default deletes the default variant's file, preserving
  today's behavior).

### 5. Fit

No new math: `catalog_view` already computes fit from `size_mb` + KV. This sub
feeds the per-variant `size_mb` through the existing `ctx_bounds`/est_ram path,
once per variant, plus once for the selected variant at the row level.

### 6. Endpoints

- Extend `POST /admin/model/profile` (sub-1) to accept an optional `quant:
  Option<String>` field, validated against `variants_for(entry)` (reject an
  unknown quant with 400). Setting it persists `ExecProfile.quant`; if the model
  is active and the quant changed, trigger a reload/switch to the new variant.
- Extend `POST /admin/model` (switch) and the DELETE handler with optional
  `quant` as described above.
- `GET /admin/models` now returns the `variants` + `quant_selected` fields.

### 7. UI

The drilldown gains a **Quant** selector listing each `VariantView`: quant tag,
size (`gb`), fit label, and download status. The current selection is marked.
Changing it and saving posts `quant` to `/admin/model/profile`; when the active
model's quant changes the existing switch/reload progress UX runs (mirrors sub-1's
`saveProfile`). Needs-download variants show their size so the user knows the
cost before switching.

## Data flow

```
dev: cargo run --bin harvest_quants → HF tree API → src/catalog_variants.rs (committed)

runtime:
  GET /admin/models → catalog_view → variants_for(entry) → per-variant fit/status
  UI select quant → POST /admin/model/profile {quant} → ExecProfile.quant
    → (if active) switch → EngineBuilder resolves files_for_quant → ensure_model → LlamaEngine::load
```

## Error handling

- Harvest: per-repo network/parse failure is logged and that repo keeps its prior
  generated data (merge rule, §1); the run warns which repos were skipped and
  which lack the default `Q4_K_M`. The generated file is written once at the end
  from the merged result, so a partial run never drops good data.
- Unknown quant in an endpoint body → 400.
- A selected quant whose files are not on disk → the switch downloads them
  first (normal switch download phase); a download failure restores the previous
  model (sub-1's existing switch-failure recovery).
- `files_for_quant` returns `None` (quant no longer in table) → fall back to the
  default file and log a warning, rather than failing the load.

## Testing

- **harvest (pure units):** the file-grouping/quant-detection logic factored into
  pure functions — split-shard grouping (`-00001-of-00003`), quant-tag matching,
  size summing — tested without network. The HTTP fetch is a thin, untested shell
  around the pure parser.
- **catalog:** `variants_for` returns the generated slice when present and the
  synthesized single-element fallback when absent; `catalog_view` produces a
  `VariantView` per variant with per-variant fit/status; the row reflects the
  selected variant; `files_for_quant` returns the right files / `None`.
- **settings/profile:** `ExecProfile.quant` round-trips; `resolve` fills
  `quant` from saved → default.
- **model_spec:** `ModelSpec` with `quant` serde round-trips and old JSON without
  `quant` deserializes to `None`.
- **endpoint:** `/admin/model/profile` persists `quant`, rejects an unknown quant;
  switch/delete honor an explicit quant.
- **load wiring:** the builder resolves `files_for_quant` and passes the variant's
  file list (verified via a seam test around the resolution helper, not a real
  Metal load).
